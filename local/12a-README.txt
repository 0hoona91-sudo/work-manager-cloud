업무관리 로컬판 12-A — 파일 실행 및 실제 폴더 저장 최소 검증

이 ZIP은 완성된 업무관리 프로그램이 아닙니다.
Codex Cloud에서는 관리자 정책이 file:// 탐색 및 파일 시스템 접근을 차단했습니다.
Windows Edge·Chrome에서의 가능 여부는 아직 확인되지 않았습니다.

1. ZIP을 PC의 고정된 위치에 압축 해제합니다.
2. 12a-folder-probe.html을 Edge 또는 Chrome으로 엽니다.
   주소가 file:///...로 시작하는지 확인합니다. 서버·확장 프로그램 설치는 필요 없습니다.
3. 기존 업무 폴더가 아닌 빈 테스트 폴더를 준비합니다.
4. “1. 테스트 폴더 선택·쓰기·읽기 검사”를 누르고 준비한 폴더를 선택합니다.
   읽기·쓰기 권한 요청이 표시되면 허용합니다.
5. 결과가 PASS인지 확인하고 Windows 탐색기에서도 실제 파일을 확인합니다.
   선택한 폴더/wm-local-probe-고유ID/data/probe-고유ID.json
   attachments, holidays, backups, journal 하위 폴더도 생성되어야 합니다.
6. “결과 JSON 내려받기”로 첫 실행 결과를 보관합니다.
7. 브라우저 창을 모두 종료한 뒤 같은 위치의 HTML을 다시 엽니다.
8. “2. 재실행 후 이전 폴더 연결·읽기 검사”를 누릅니다.
   권한 재요청을 승인하고 결과 JSON을 별도로 보관합니다.
9. Edge와 Chrome은 각자 별도의 테스트 폴더로 확인합니다.
   브라우저 이름·버전, Windows 버전, 단계별 성공/오류를 기록합니다.

2번 버튼이 비활성화되거나 권한을 다시 얻지 못하면 재연결 성공으로 판단하지 않습니다.
파일 쓰기가 성공했어도 브라우저 기록 보관에 실패하면 재실행 조건은 미충족입니다.
관리 정책으로 차단된 경우 정책을 임의로 해제하지 않습니다.
이 도구는 브라우저가 완전히 종료됐는지를 스스로 입증하지 못합니다.
전체 종료·재실행 여부는 사용자가 확인해야 합니다.

실제 파일은 선택한 PC 폴더에 저장합니다. IndexedDB는 폴더 핸들과 검사 문자열만 보관합니다.
인터넷 요청, Firebase, Drive, 로그인, 업무 데이터 업로드는 없습니다.
기존 파일 삭제·자동 정리·자동 복원 기능은 없습니다.
테스트 완료 후 실험용 폴더는 사용자가 탐색기에서 확인 후 직접 정리할 수 있습니다.

아직 미구현: 최신 업무관리 UI 이식, 로컬 저장 엔진, 첨부 원본 관리,
공식 공휴일 자료, 백업·복원, 다중 실행 보호 및 전체 기능 검증.

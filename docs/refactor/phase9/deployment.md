# 운영 반영 전 확인과 롤백

9단계 브랜치는 운영 `main`, GitHub Pages, Firebase/Firestore, Security Rules, Google Drive에 적용하지 않았다. 실제 계정·운영 업무 자료도 조회하지 않았다.

운영 반영 전에는 GitHub Pages의 `/work-manager-cloud/` 하위 경로에서 `./assets/shared-hello-kitty-bg-68137d.webp?v=phase9`가 200으로 로딩되는지, 모바일 320/390px와 데스크톱·테마 전환 시 이미지·레이아웃이 유지되는지 확인해야 한다. 이전 오프라인 캐시나 오래된 HTML과 신규 asset의 배포 순서가 어긋나면 테마 배경이 누락될 수 있으므로 HTML과 자산을 함께 배포하고 캐시를 점검한다. 실제 운영 검증 및 배포는 별도 사용자 승인 사항이다.

1만 합성 업무에서 기존과 현재 모두 홈 Gantt가 `Invalid string length`로 실패한다. 이는 대량 업무 환경의 미해결 한계이며 운영 데이터의 규모·분포로 실측하지 않았다. 1천 건 업무 목록 렌더는 이 표본에서 약 7% 느리게 측정되어 후속 모니터링이 필요하다. 이벤트·observer 정량 측정, 다른 브라우저·오프라인 캐시, 실제 계정/Drive 호출은 수행하지 않았다.

문제가 생기면 운영 배포를 중단하고 8단계 기준 커밋 `daa15a100837ad4f3aeca2e31136041bf48ad10f`의 파일 세트를 다시 배포한다. 개발 브랜치에서는 관련 9단계 커밋을 역순 `git revert`하여 이력을 보존한다. 데이터 형식과 ID는 바꾸지 않았으므로 데이터 롤백·마이그레이션은 필요하지 않다. force push는 하지 않는다.

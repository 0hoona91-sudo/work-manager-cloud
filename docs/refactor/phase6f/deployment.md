# 운영 전환과 6단계 종료 범위

이번 작업은 개발 브랜치와 demo Emulator에 한정한다. 실제 운영 규칙/데이터/Google Drive는 조회·변경하지 않았다. 생성된 규칙은 표시만 하며 실제 적용에는 별도 사용자 승인이 필요하다.

## 승인 후 운영 전 통합검증

1. 실제 개인 Firebase 프로젝트와 UID/추가 승인 UID를 확인한다. 업무공간의 승인 목록은 Firestore 접근 범위다. 앱의 로비 Google 승인 정책까지 자동 확대하는 기능은 아니다. 테스트 UID와 demo 프로젝트를 운영에 복사하지 않는다.
2. 실제 규칙을 별도 승인 후 확인한다. 좁은 allow와 기존 recursive wildcard는 OR로 평가되므로 안내 규칙을 일부 추가하는 방식으로 적용하지 않는다. 전체 규칙·컬렉션·공동 UID 정책을 검토한다.
3. 별도 승인된 읽기 전용 자료로 preflight를 실행한다. 누락 잠금/잘못된 소유권/비표준 ID/tombstone 충돌/orphan 체크/이상 revision은 자동 보정하지 않는다. 조사 대상·영향·복구본을 제시한 뒤 수정/마이그레이션은 다시 승인받는다. 기존 키만 있고 canonical lock이 없는 자료는 일반 저장에서 보류될 수 있다.
4. 미확정 journal과 SDK offline 대기 쓰기의 존재를 확인한다. 자동 삭제·강제 재전송하지 않는다. 구형 앱 캐시와 기존 복사 규칙 안내는 새 정책 버전으로 교체해야 한다. 새 index/module URL은 갱신했지만 이미 열려 있는 구형 탭·오프라인 브라우저까지 즉시 교체됐다는 보장은 없다.
5. 호환 앱을 먼저 별도 승인·배포하고 계정별 재로그인/새로고침·복구 작업 확인을 마친 뒤 강화 규칙을 승인·배포한다. 구형 revision 없는 쓰기가 permission-denied가 되는 것은 예상된 보호다. 전환 중 편집 보류 및 사용자 안내가 필요하다.
6. 비운영 실계정 환경에서 실제 Google 로그인, 개인 Firebase Auth, Drive 권한, 첫 생성·재연결, 다중 UID, 웹브라우저 SDK 전체 흐름을 검증한다. Emulator의 합성 인증 토큰/모의 bootstrap은 이를 대신하지 않는다.

## 남은 문제의 분류

| 항목 | 담당 범위 |
|---|---|
| 실제 UID/운영 규칙·데이터 현황, 배포 순서·오프라인 캐시 | 운영 전 통합검증, 사용자 승인 필요 |
| legacy 잠금/자료 정리·ID/스키마 변환 | 사용자 승인 후 별도 자료 정비; 자동 실행 금지 |
| Drive·첨부·백업·Google Tasks 구조와 BUG-01 | 다음 예정 개발 7단계 |
| BUG-02 CSS, BUG-08 체크 표시, BUG-09 projectResources | 관련 UI/데이터 후속 단계에서 범위 확정 |
| 다중 청크/IndexedDB-Firestore 전역 원자성, 모든 구형 경로의 의미적 충돌 | 후속 저장/운영 검증 위험; 이번 범위의 보장을 확대하지 않음 |
| 새로 발견되는 심각한 보안/자료 손실 위험 | 위험과 대응 범위를 사용자에게 제시; 독자적 6-G 생성 금지 |

## 롤백

미배포 개발 브랜치의 6-F 커밋만 revert하면 기준 6-E로 돌아갈 수 있다. main reset·force push·데이터 삭제·잠금 재발급이 필요하지 않다. 기존 생성기로 돌아가는 코드를 운영에 배포하면 recursive allow 안내가 부활하므로 이를 안전한 운영 rollback으로 사용하면 안 된다. 운영에는 승인된 규칙/클라이언트를 함께 유지하고 새 편집을 보류한 상태에서 복구 절차를 검토해야 한다. journal과 복구본은 보존한다.

6-F 완료 판정은 개발 환경 통합 완료에 대한 것이다. 운영의 모든 위험 제거를 뜻하지 않는다. 완료 조건을 충족하면 6단계를 종료하고 7단계에 착수할 수 있으며, 6-G/6-H를 자동 추가하지 않는다. 7단계의 실제 구현은 다음 지시 범위에서 진행한다.

## 최종 결정

최종 성공 CI와 완료 조건 대조 결과 6-F 개발 완료로 판정한다. 6단계를 종료하고 7단계 개발 지시를 받을 수 있다. 위 운영 승인·검증 항목은 6-F의 미완료 개발이나 자동 6-G 사유로 간주하지 않는다. 새로운 중대한 보안/자료 손실 위험이 드러나면 그 근거를 제시하고 범위 판단을 요청한다.

# 롤백과 복구 경계

코드 문제는 검증된 직전 Pages 정적 파일 세트로 되돌리고 캐시·asset 버전을 함께 맞춘다. Git 이력은 `git revert`로 보존하며 force push하지 않는다. 이전 클라이언트가 새 Security Rules에서 쓰기를 못 할 수 있으므로 코드만 되돌려 정상 복구됐다고 판단하지 않는다. 규칙 변경이 있었다면 승인된 운영 담당자가 보관한 원본 규칙과 데이터 접근 계약을 별도로 비교해야 한다.

Firestore 데이터와 Drive 파일은 Pages 코드 롤백만으로 되돌아가지 않는다. 배포 전 JSON 구조 백업은 첨부 원본을 포함하지 않으므로, 원본 포함 ZIP의 manifest·누락 목록과 별도 Drive 보존 계획이 필요하다. 복원은 3-D 미리보기·충돌 처리·명시적 승인 절차를 거쳐야 한다. 일부 Firestore 쓰기와 Drive 업로드를 하나의 원자적 작업으로 되돌릴 수 없으며, 미확정 operation journal과 첨부 복구 기록을 강제로 삭제하지 않는다.

중단 기준: 완료 이력 손실, 반복 회차 중복, 타 계정 자료 노출, 규칙 오거부, 미확정 저장을 성공으로 표시, 첨부 원본 누락 또는 심한 화면 접근 불가. 발생 시 쓰기를 멈추고 당시 SHA·규칙 버전·journal·백업 manifest를 보존한 뒤 원인과 영향 범위를 확인한다. 운영 데이터 직접 수정은 별도 승인 없이는 하지 않는다.

# 운영 배포 계획 — 실행 전 승인용

이 문서는 배포 명령이 아니다. 최신 원격 main `091dbecd701153e7e1880bd6bb84a277b789c58f`는 이 브랜치 기준 이력의 조상이며, 1~10단계 변경은 아직 main에 병합되지 않았다. 실제 배포 전 main 변동을 다시 비교해야 한다.

1. 사용자 승인 후 실제 운영 규칙과 Google OAuth/Drive 테스트 환경, 운영 업무 규모를 확인한다. 미확정 journal·오프라인 대기 작업·구형 브라우저 캐시가 있는 사용자를 파악하고, 필요한 JSON 및 첨부 원본 백업을 구분해 준비한다.
2. 빌드가 없는 정적 Pages 파일 세트를 하나의 검증된 SHA에서 준비한다. `/work-manager-cloud/` 상대 경로, Hello Kitty WebP, JS/CSS 버전 쿼리, PWA/캐시 순서를 staging 또는 격리 환경에서 확인한다. source map/debug·비밀정보가 산출물에 없는지 다시 검토한다.
3. 새 클라이언트의 일반 업무·프로젝트·반복·백업·journal 동작과 실제 OAuth·Drive 파일 접근을 승인된 테스트 계정으로 검증한다. 이전 클라이언트가 부모 revision 없이 쓰는 요청은 새 규칙에서 거부될 수 있으므로 캐시 갱신·재로그인·대기 기록 확인 방법을 먼저 안내한다.
4. 별도 승인으로 main 병합/Pages 배포 및 Security Rules 전환 순서를 결정한다. 한 번에 동시 적용했다고 원자적이라고 주장하지 않는다. 운영 규칙 변경은 실제 기존 규칙 diff와 롤백 원본을 확보한 뒤에만 진행한다.
5. 배포 직후 인증·업무 읽기/쓰기·완료 이력·반복 생성키·프로젝트·첨부·JSON/ZIP·모바일·테마·로그아웃을 소수 테스트 계정으로 확인하고, 충돌·복구 필요 상태를 모니터링한다. 오류가 있으면 [rollback-plan.md](rollback-plan.md)의 중단 기준을 따른다.

실제 OAuth/Drive, 운영 규칙, 운영 자료 규모가 미확인인 현재는 **운영 배포 준비 완료 판정 불가**다. 배포 승인과 운영 테스트 계정 제공은 사용자 결정 사항이다.

# 운영 전 검증과 롤백

## 개발 범위와 승인 경계

작업은 `refactor/phase7-google-file-adapters`와 합성 데이터에 한정했다. main 병합, Pages 배포, 운영 Firebase/Rules 조회·쓰기, 실제 Drive/Google Tasks 파일 요청은 하지 않았다. 강화 규칙의 운영 반영은 기존 6-F 전환 계획과 별도 사용자 승인이 필요하다.

운영 반영 전에 승인된 별도 계정·검증 자료로 다음을 확인한다.

- Google 로그인·Drive 재승인·취소·만료·401/403 및 계정/업무공간 변경. 이번 인증 검사는 모의 SDK/HTTP다.
- 현재 Drive scope에서 `files.generateIds`, 지정 ID 생성, 업로드, 크기/체크섬 조회가 가능한지 확인한다. 응답 유실 시 같은 ID 확인·재시도와 일반 이미지/PDF 열기·능동 문서 다운로드를 검증한다.
- 실제 브라우저의 IndexedDB 정책/할당량, 새로고침, 로그아웃 후 동일 계정 복귀, 첨부 저장 확인 화면을 확인한다. 진단은 현재 계정·업무공간으로 제한한다.
- 운영 자료를 자동 정리하지 않고 JSON/ZIP 표본을 별도 보관해 참조·누락 manifest·SHA-256을 대조한다. 대형 자료는 제한 범위로 나누어 백업한다.
- 캐시된 구형 클라이언트와 미확정 저장/journal을 먼저 확인한 후 클라이언트와 규칙을 기존 6-F 순서대로 전환한다. 미확정 기록을 지우지 않는다.

## 남은 한계

- Drive와 Firestore 사이의 전역 트랜잭션은 없다. 업로드 완료와 참조 저장 확정은 별개다. 구형 저장 경로/부분 Firestore 성공은 복구 확인이 필요할 수 있다.
- 첨부 journal은 같은 브라우저·계정·업무공간에서 원본 파일을 다시 선택할 때 동일 ID로 복구한다. 다중 탭/기기의 파일 업로드 자체에 대한 전역 중복 방지는 보장하지 않는다. 이미 전송된 HTTP는 취소/로그아웃으로 되돌릴 수 없다.
- 브라우저 저장소가 외부에서 삭제되면 journal 복구가 불가능하다. 앱의 로컬 초기화는 journal을 보존하지만 이를 외부 백업으로 간주하면 안 된다. 파일명/ID 등 업무 정보가 journal/백업에 남으므로 PC와 백업 파일 접근을 보호해야 한다. 인증 토큰·비밀번호는 첨부 journal에 넣지 않는다.
- 고아 파일은 진단만 한다. 활성 참조가 있는 원본이나 미확정 파일을 자동 삭제하지 않는다. 기존 파일의 내용/크기가 다르면 자동 덮어쓰기 대신 수동 확인이 필요하다.
- Drive 응답의 SHA-256 필드가 제공되면 비교하지만 없는 응답은 ID·크기 확인만 가능하다. 실서비스 체크섬 제공 여부는 미검증이다.
- ZIP은 메모리 기반 기존 writer다. 단일 50MiB/총 200MiB/1000개 제한을 두며 메모리 여유에 따라 더 보수적으로 누락을 보고할 수 있다. 취소는 후속 처리/다운로드를 중단하며 이미 읽은 요청을 되돌리지 않는다.
- JSON은 외부 원본을 포함하지 않는다(기존 인라인 데이터는 유지). 인수인계 ZIP은 읽기 전용 자료이며 자동 원본 복원 포맷이 아니다. ZIP manifest의 SHA-256 대조와 압축 해제는 별도 확인이 필요하다. 데이터 복원은 기존 JSON 미리보기·충돌 승인을 이용한다.
- BUG-02 CSS, BUG-08 checklist 객체 표시, BUG-09 projectResources 직렬화의 기존 XFAIL은 이번 범위 밖이며 그대로 남는다.

## 롤백

운영 배포를 하지 않았으므로 현재 운영 롤백은 필요 없다. 개발 브랜치에서는 `git revert`로 필요한 커밋을 역순 되돌리고 관련 검사를 수행한다. reset/force push는 사용하지 않는다. A/B를 보존하려면 C `d74ce77`, D `2c27c9b`, 통합 `fba8ac8`, UI 수정 커밋의 의존 관계를 함께 검토한다. C 이전 코드로 되돌리면 기존 실패 시 파일 삭제 동작도 복원될 수 있으므로 실제 운영에 그대로 적용하지 않는다. 롤백 과정에서도 Drive 원본·업무 ID·completionHistory·generatedKey·복구/첨부 journal을 삭제하거나 변환하지 않는다.

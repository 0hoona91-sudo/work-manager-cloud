# 3단계 추천 작업

이번 단계에서는 운영 코드를 수정하지 않았다. 아래 작업은 다음 단계의 별도 지시 이후 수행한다. 테스트 기대값은 안전 요구의 최소 계약이다. 백업 충돌 UI, 완료 기록 보관 방식 등 제품 정책을 결정하면 원하는 정책을 더 구체화해야 한다.

| 우선순위 | 문제 / 테스트 | 권장 수정 단위와 검증 |
|---|---|---|
| P0 데이터 유실 | 완료 업무 재개·삭제, 백업 덮어쓰기 / BUG-04,05,07 | 완료 이력을 암묵적으로 수정하지 않는 공통 규칙을 먼저 분리한다. 편집·명시적 재개·보관·복원 충돌을 구별한다. 보관 구조 도입 전 호환성 검증과 사용자의 정책 결정이 필요하다. 현재 보존 assertion을 유지하며 선택한 정책의 추가 테스트를 먼저 작성한다. |
| P0 일정 중복 | `cycleMonths`, `half`, 영속 생성 키 누락 / BUG-10,11,12 | 기존 필드의 해석을 공통 반복 엔진으로 통합한다. 회차의 결정적 키를 정의하고 기존 schema11 생성 잠금과 연결한다. 메모리 재실행뿐 아니라 동시 기기/재시작 충돌 테스트를 추가한 뒤 저장 연계를 수정한다. |
| P1 일정 불일치 | 완료 기준일 복원 순서·UTC+14 음수 offset / BUG-03,06 | 완료 단계 고정 후 종속 일정을 계산한다. 달력 날짜 연산을 순수 함수로 통합한다. 현재 정상 offset·주말·윤년 테스트를 유지하고 여러 단계·시간대 검사를 보강한다. |
| P1 저장 호환 | 객체 체크리스트 문자열화·task 첨부 raw data / BUG-08,09 | 입력 경계에서 명시적 변환/검증과 일관된 첨부 메타데이터 처리를 수행한다. object-form을 계속 지원할지 명시적으로 거부할지 정책을 정하되 `[object Object]`로 조용히 저장하는 동작은 허용하지 않는다. 기존 정상 schema11 왕복을 유지한다. |
| P1 시작 장애 | Tasks 모델 누락 / BUG-01 | 기대 API와 연동 계약의 테스트를 먼저 추가한 뒤 누락 모듈을 복구하거나 기능 경계를 정리한다. 가짜 빈 모듈로 import만 통과시키지 않는다. |
| P2 화면 CSS | 대시보드 닫는 중괄호 오류 / BUG-02 | CSS 한 블록 수정 후 문법과 핵심 화면을 검증한다. 시각 비교는 이 수정 단계에서 필요한 크기로 한정한다. |

권장 순서: 완료 이력/복원 보호 → 반복 생성 계약 → 날짜 계산 엔진 → 저장 어댑터 → 시작 모듈과 UI 책임 정리. 시작 장애를 먼저 처리해야 실제 브라우저 검증이 가능한 작업에서는 BUG-01을 독립 소규모 변경으로 앞당길 수 있다.

각 작업은 작은 기능 단위 커밋으로 진행한다. 수정 전 실패하는 테스트를 먼저 추가하고, 해당 버그가 고쳐지면 XPASS를 정상 PASS로 승격한다. `npm test`에 새 FAIL/NOT_RUN이 없어야 하며 정상 fixture가 보존되어야 한다. 운영 데이터 마이그레이션·배포는 별도 승인 범위다.

1단계 고위험 항목 중 아직 자동화하지 않은 영역도 남아 있다: all-holiday 날짜 반복 상한, 저장 재시도/큐 경쟁, MutationObserver·render 재진입, Drive 토큰 수명/재인증, 파일 업로드 실패, 대용량 복원, 인증 후 전체 화면 흐름. 해당 책임을 수정하기 전에 mock/emulator 또는 제한된 UI 테스트를 먼저 마련한다. 이번 33개가 그 영역의 안전성을 보증하지 않는다.

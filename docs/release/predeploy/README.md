# 운영 배포 후보: 확인된 결함과 수정

기준은 10단계 최종 `6b96ba6ff9a9c924fcfdf7a72e50b0c67af02dd6`이며 이 브랜치는 `main`에 병합하지 않았다.

- 프로젝트 저장: 구형 일반 저장 경로가 다른 기기의 프로젝트·단계·체크리스트 변경을 확인하지 않아 조용히 덮어쓸 수 있었다. 프로젝트 UI에서 명시적인 `projectSave` 명령을 보내고, 서버 트랜잭션 안에서 프로젝트·변경 문서·연결 단계 및 기존 체크 항목의 기준값을 검사한다. 다른 단계의 독립 메모 수정만 보존하며 날짜·완료·체크 충돌은 입력을 유지하고 거부한다. 오프라인 저장, 중복 큐, 트랜잭션 청크 분할을 보류한다. 클라우드 로컬 캐시는 서버 확정 뒤에만 갱신한다. 관련 파일: `js/project-ui.js`, `js/cloud-sync.js`, `index.html`.
- 구형 캐시: 새 HTML에 수정된 모듈 버전 쿼리를 부여했다. 옛 HTML과 새 `cloud-sync.js`가 섞여 실행되면 명확한 업데이트 오류와 함께 쓰기를 거부한다. 구형 오프라인 큐·journal·기존 자료는 지우지 않는다. 기존 HTML+구형 JS는 새 코드만으로 통제할 수 없어 배포 순서와 사용자 갱신 안내가 필요하다.
- 일반 업무 목록: 1천 건 이하의 기존 전체 표시를 보존하고, 이를 넘는 결과에 500건 단위 명시적 페이지 선택을 적용했다. 필터·검색은 전체 업무에 먼저 적용하고 화면 행만 나눈다. 다른 페이지에서 고른 일반 업무의 선택을 유지하면서 프로젝트 단계의 숨은 선택은 제거한다. 업무 원본·저장·백업·ID는 그대로다. 관련 파일: `index.html`, `js/workflow-reform-v17.js`.

신규 검사는 `tests/release-predeploy.test.cjs`, 재현 가능한 동일 Chromium 측정은 `tests/release-list-benchmark.cjs`와 `list-benchmark.json`이다. 10단계의 424개 검사 ID·계약은 삭제하거나 완화하지 않았다.

# 운영 반영 전 남은 차단 조건

개발 브랜치의 합성 검사 성공을 실제 운영 준비 완료로 간주하지 않는다. 다음은 **배포 실행 전** 승인된 테스트 환경과 사용자 판단이 필요하다.

1. 승인된 별도 Google 계정·OAuth 승인 도메인·격리 Drive 폴더에서 로그인/재인증/계정 변경/업로드/원본 포함 백업을 실측한다. 제공되지 않아 실제 OAuth·Drive API는 호출하지 않았다.
2. 실제 운영 Firebase 프로젝트의 기존 Security Rules 원본과 승인 UID를 보관·비교하고, 기존 데이터의 생성키 잠금·체크리스트 부모 revision·오프라인 대기 기록을 읽기 전용으로 사전 점검한다. 현재 운영 규칙·데이터는 조회하지 않았다. legacy 불일치가 발견되면 사용자 승인 없는 자동 마이그레이션은 하지 않는다.
3. 구형 HTML+구형 JS 또는 오래된 오프라인 탭은 새 코드의 버전 보호가 작동하지 않는다. 새 클라이언트를 먼저 배포하고 탭 새로고침·대기 저장/journal 확인을 끝낸 뒤 강화 규칙을 별도로 적용한다. 기존 Rules의 허점이 남는 전환 기간에는 편집 중지 등 운영 통제가 필요하다.
4. 프로젝트 동시 저장은 관련 문서가 한 트랜잭션에 들어갈 때만 허용한다. 대형 프로젝트의 320쓰기/규칙 접근 예산 초과, 응답 유실 뒤 영속 프로젝트 journal 부재, 구형 저장 경로와 IndexedDB·Firestore 간 원자성 부재가 남는다. 모호한 결과는 재전송하지 말고 서버를 확인해야 한다.
5. 1만 건 합성 목록은 개선됐지만 실제 자료 규모·저사양 모바일·프로젝트 복잡도·브라우저 메모리 사용량은 확인되지 않았다. 실제 데이터 규모를 승인된 읽기 전용 절차로 확인한다.

이 조건이 확인·승인되기 전에는 main 병합, Pages 및 운영 Rules 변경을 실행하지 않는다.

# Sites 연결 후보

이 폴더는 실제 Sites 배포 번들이 아닙니다. 현재 확인된 공식 규격과 이식할 SQL만 담습니다.

- `identity.mjs`: 공식 로그인/로그아웃 경로와 플랫폼 사용자 헤더를 읽는 순수 경계 함수. 검증되지 않은 ingress는 기본 거부. 제품 서버에는 아직 연결하지 않았습니다.
- `001_initial.sql`: 로컬 SQLite에서 실행·반복 적용을 확인한 D1 후보 schema. 실제 D1에서 미실행입니다. 테스트용 테이블은 포함하지 않습니다.

Sites 도구가 있는 환경에서 공식 starter를 생성한 후 실제 지원 런타임과 binding을 확인해야 합니다. 문서에 나오지 않은 SDK 이름, 배포 ID, API 또는 런타임을 만들어 넣지 않았습니다.

연결 시 할 일:

1. 플랫폼의 헤더 위조 방어 및 직접 origin 우회 방지 확인.
2. 이 함수가 반환한 issuer/subject를 서버 DB 사용자 UUID에 연결. 이메일 변경 정책 확인.
3. 각 요청의 플랫폼 사용자와 앱 세션 사용자 일치 확인. 계정 전환 시 이전 세션 폐기. 로그아웃은 플랫폼과 앱 양쪽 처리.
4. 소유권 검사 API/Google OAuth 로직을 실제 서버 런타임으로 연결하고 D1 영속성과 원자적 작업 재검증.
5. Google token 암호화를 해당 런타임의 검증된 crypto API로 구현. 현재 Python Fernet 구현을 호환성 확인 없이 그대로 작동한다고 주장하지 않기.
6. 정적 UI의 로그인/로그아웃을 실제 플랫폼 경로에 연결한 뒤 두 계정 E2E 테스트.

세부 설정 위치: [Sites 확인 보고서](../docs/02-sites-findings.md).

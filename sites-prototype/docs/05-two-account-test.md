# 두 사용자 계정의 데이터·첨부 분리 검증

## 이미 실행한 자동 검증

`tests/test_api.py`와 `tests/browser_smoke.py`가 임시 DB에 A/B 사용자와 세션을 만든다. 제품의 로그인 API를 흉내 내는 UI/endpoint는 없다. 자동 테스트의 identity fixture는 실제 ChatGPT 로그인 검증을 대신하지 않는다.

브라우저 테스트는 독립된 두 Chromium context에서 A의 업무 등록·저장·상태 변경·파일 업로드/조회/다운로드와 B의 차단을 확인한다. 별도 API 테스트에서는 Google 서명 토큰/JWKS/OAuth/Drive 모의 서버로 같은 서버 코드를 검증한다.

## 실제 ChatGPT/Google 계정 2개로 수행할 검증

준비: 제한 공유된 실제 Sites URL, 연결된 D1/플랫폼 신원, Google OAuth 설정, ChatGPT 사용자 A/B, 서로 다른 Google 계정 GA/GB. 같은 브라우저의 탭 2개는 쿠키를 공유하므로 서로 다른 브라우저 프로필 또는 완전히 분리된 private context를 사용한다.

| 순서 | 수행 | 기대 결과 |
|---|---|---|
| 1 | 로그인하지 않고 업무 목록/API/첨부 URL 요청 | 미연결 안내 또는 ChatGPT 로그인 안내. 데이터 API 401. 파일 내용 없음 |
| 2 | A로 ChatGPT 로그인, 업무 `A-전용-점검` 저장 후 새로고침 | A 신원 표시, 저장된 업무 유지 |
| 3 | A에서 GA 연결, `A-private.txt` 업로드 | 동의 후 전용 폴더 자동 생성, 파일/메타데이터 유지 |
| 4 | A에서 첨부 조회·다운로드 | 원문 일치. 바이너리 SHA-256 비교도 일치 |
| 5 | B로 ChatGPT 로그인 | A 업무/메모/첨부/Google 이메일이 보이지 않음 |
| 6 | B가 A의 `/api/tasks/{id}` 직접 요청 | 404. 다른 사용자의 존재/내용을 노출하지 않음 |
| 7 | B가 A의 업무 수정 또는 첨부 업로드 요청 | 404. A의 데이터는 변경되지 않음 |
| 8 | B가 A의 첨부 metadata/content URL 요청 | 모두 404. Google API를 호출하기 전에 서버에서 거부 |
| 9 | B에서 GB 연결 후 업무·파일 저장 | B의 별도 연결/폴더 사용. A에게 B 데이터가 보이지 않음 |
| 10 | B에서 GA를 연결하려 시도 | 이미 연결된 Google subject 충돌로 거부. 기존 연결 유지 |
| 11 | A에서 로그아웃 후 이전 파일 URL 접근 | 401. Sites 플랫폼과 앱 세션 양쪽 로그아웃 확인 |
| 12 | A→B로 계정 전환, 이전 탭 새로고침 | A 데이터/미리보기/cache가 남지 않고 현재 사용자만 표시 |
| 13 | A 재로그인 후 재조회 및 서버/사이트 재시작 | 같은 사용자 데이터와 Google 연결 복원 |
| 14 | OAuth state 바꾸기, 다른 세션 callback, callback 재실행 | 400/401. 연결이 다른 사용자에게 이전되지 않음 |
| 15 | A의 Google 권한 철회/만료 후 파일 접근 | 오류/재연결 안내, 다른 사용자 토큰으로 대체하지 않음 |
| 16 | 파일 크기 초과, 잘못된 제목/상태, HTML 파일 | 적절한 입력 거부 또는 안전한 첨부 다운로드. HTML 스크립트 실행 없음 |

테스트 중 A의 업무 UUID와 첨부 UUID만 B에게 전달한다. 세션 쿠키, CSRF 토큰, OAuth code/token을 공유하지 않는다. B의 변경 요청에는 B 자신의 세션과 CSRF 토큰을 사용한다.

현재 독립 API에서 B의 권한으로 읽기 테스트를 할 때 브라우저 개발자 도구 예시:

```js
// B로 로그인한 브라우저에서 실행. A_TASK_ID/A_FILE_ID만 테스트 기록에서 대입.
await fetch('/api/tasks/A_TASK_ID').then(r => r.status); // 404
await fetch('/api/attachments/A_FILE_ID/content').then(r => r.status); // 404
```

Sites 어댑터로 전환한 후에도 같은 접근 차단 의미를 유지해야 한다. 실제 API 경로를 바꾸면 테스트도 함께 갱신한다.

실계정 결과 기록에는 사이트 버전/커밋, 브라우저, 검사일, 계정 별칭(A/B), 각 행의 성공·실패·미실행을 기록한다. 실제 사용자 이메일·파일 내용·토큰은 공개 GitHub 보고서에 올리지 않는다. 현재 이 표는 **실계정 미실행**이다.
